🧮 Worked Example — One Token's Journey, Stage by Stage (schematic arithmetic)

Say the text is "Hi!". The tokenizer produces ids; the engine looks up each id's row in the 97×24 table wte. The rest of the journey acts on this 24-dim vector. Below, each stage shows its real shape — the arithmetic uses a schematic d = 4 reduction so the numbers fit on a line (the engine really does d = 24).

"H" → id 40 → x = wte[40] ∈ ℝ²⁴   (schematic: x = [0.31, −0.12, 0.55, 0.08])

Layer 1, path A — RMSNorm rescales the vector to unit RMS, then attention projects it into 3 heads of 8 dims, rotates q and k by the position angle (RoPE), scores against every past key, softmaxes, and blends the values:

a₁ = Attn(RMSNorm(x)) ∈ ℝ²⁴  ·  x ← x + a₁

The residual add keeps the original embedding present — nothing is overwritten (7.6 is devoted to this).

Layer 1, path B — SwiGLU gates the token's own features: 24 dims project to 64, half of them gate the other half through SiLU, and the product projects back to 24:

m₁ = (silu(xWg) ⊙ xWu) Wd ∈ ℝ²⁴  ·  x ← x + m₁

Layers 2 and 3 repeat the same two paths — attention only ever mixes tokens; the MLP only ever transforms each token alone.

The finish — final RMSNorm, then a dot product against every row of wte (the tied unembedding). The result is 97 logits; softmax turns them into a probability distribution over the next character:

logits = RMSNorm(x) · wteᵀ ∈ ℝ⁹⁷  ·  p = softmax(logits)

→ Seven stages, one token, real numbers. Everything downstream of your text is computed live on this page — start in 7.2.

SECTION 7.3 ★

The Embedding Observatory — One Row Per Token, Rotated in Place

The token id is not a number the model understands — it is an address. The embedding table wte holds a 24-dim vector at every address, and that vector is what actually enters the tower. This lab reads real rows from the table, and then shows the one twist this engine adds: RoPE, which rotates queries and keys by their position instead of adding a position vector.

🎯 By the end of this section, you will be able to read a token's embedding row as a vector, and explain exactly what RoPE rotates, when it rotates it, and why the stored row never changes.

Watch the table: each row is a fixed vector — wte[id] — and the bars to the right are its 24 components. The row below the bars shows what happens at attention time: RoPE takes q/k pairs (dims 0–1, 2–3, …) and rotates each pair by an angle that grows with position. The stored row is untouched; the rotation happens to a copy, inside the attention head.
$$\text{RoPE}(x, p)_i = \begin{pmatrix} \cos p\theta_i & -\sin p\theta_i \\ \sin p\theta_i & \cos p\theta_i \end{pmatrix} \begin{pmatrix} x_{2i} \\ x_{2i+1} \end{pmatrix}, \qquad \theta_i = \text{base}^{-2i/d_{head}}$$

Why rotate and not add? Adding a position vector makes position absolute — the model must memorize each offset. Rotating q and k makes their dot product depend only on relative position: a rotation by p₁ followed by a rotation by p₂ differs by a fixed rotation p₂−p₁, so qp₁·kp₂ sees the same geometry whether the tokens sit at (5, 7) or (105, 107). Relative position is what language actually cares about.

🧭
Where the angles come from: θᵢ = 10000^(−2i/8) for our 8-dim heads — i = 0 rotates fastest, i = 3 slowest. The lab draws the four pairs of this engine's head: pair 0 completes a full turn roughly every 2π positions — more than three full turns by position 24; pair 3 moves less than 0.03 rad. Real models (Llama, Mistral, Qwen) use the same formula with d_head = 64–128 and bases up to 500,000 for long contexts.
📓 Instruction Manual · RoPE — The Rotation That Costs Zero Parameters

Page 1 · Absolute positions, and why they're a trap

R1Learned absolute position embeddings (Module 02's sinusoidal cousins) add a position-dependent vector to the embedding. Problem: "token at position 5" and "token at position 5,005" are different vectors the model must learn separately — and positions beyond the training window have no vector at all. GPT-2 (1,024 tokens) literally cannot be run on 1,025.

$$x_p = \text{embed} + \text{posvec}(p) \qquad \text{(learned absolute — position baked into the input)}$$

Page 2 · Rotation encodes relative distance

RoPE (Su et al., 2021 — "RoFormer") rotates the queries and keys instead. A 2×2 rotation by angle pθᵢ applied to each dim-pair has a beautiful property: the dot product of two rotated vectors depends on the difference of their angles, and the difference of the angles is proportional to the position difference:

$$R(p\theta) q \cdot R(p'\theta) k = q \cdot R\big((p'-p)\theta\big) k \qquad \text{— relative position, exactly}
And it costs zero parameters: the angles are pure math, computed on the fly. This is why every modern open model — Llama, Mistral, Qwen, Gemma — runs RoPE or a variant of it. The lab above is literally the formula in motion.

Page 3 · The extrapolation caveat

RoPE can in principle run at any position — no table to run out of — but in practice attention quality decays beyond the training window, because the model never learned to use large rotation angles. The fix in real systems is to extend the base (e.g., 500,000 for Llama-3's 128K context): the same formula, slower angles, so positions the model never saw land on angles it has seen.

Honest note for this module: our engine has no training at all, so "extrapolation quality" is moot — the point is the mechanism. The mechanism you just watched — four pairs, four speeds, one formula — is the identical one running in production models.

🔮 Predict Before You Compute
RoPE rotates the query and key vectors at attention time. What happens to the embedding vector stored in wte?
Nothing — the stored row is untouched. This is the whole difference from Module 02's learned embeddings: position enters the computation inside attention (on q and k), not at the table. The embedding row for "t" is the same vector at position 0 and position 23; only the q/k copies get rotated, which is exactly why RoPE has zero parameters and why the dot product becomes position-relative for free.

🧮 Worked Example — Reading one cell and one row, from the engine's own numbers

Pick any query row i and key column j. The engine computes the score in three moves — project, rotate, dot:

score(i, j) = RoPE(qi) · RoPE(kj) / √8

Hover a cell to see its two numbers: the scaled score before softmax, and the final weight after. They differ because the row is normalized against its own exponentials.

Now take the full row for query i and softmax it — the causal mask means only j ≤ i participate:

wij = exp(score(i,j)) / Σj'≤i exp(score(i,j'))

Row 0 has exactly one surviving cell (itself), so its weight is 1.000 — the first token of any causal model attends only to itself. That is not a learned choice; it is geometry.

The blended output — the actual value that leaves the head:

outi = Σj≤i wij · vj  ∈  ℝ⁸ per head, then concat + WO → ℝ²⁴

→ Three heads per layer, three layers: nine matrices on this page, every cell readable. With trained weights you would hunt here for interpretable roles (previous-token heads, induction heads — Module 12). With toy weights, you are hunting noise — and knowing the difference is the lesson.

$$\text{Attn}(X) = \text{softmax}\!\left(\frac{Q K^{\top}}{\sqrt{8}} + M\right) V, \qquad M_{ij} = \begin{cases} 0 & j \le i \\ -\infty & j > i \end{cases}$$

Why the mask is −∞, not deletion: e^(−∞) = 0 exactly, and the softmax denominator renormalizes the survivors — rows keep summing to 1. This is the exact discipline from Module 04, now running inside the full engine with RoPE'd vectors.

🔮 Predict Before You Compute
In a causal transformer, the attention row of the FIRST token (position 0) has how many possible keys to attend to?
Exactly one — itself. Row 0 of every causal matrix contains a single surviving cell, and softmax of a single cell is 1.000 by definition. You can verify it on the canvas: select row 0 and read the bars. This is the purest demonstration that the mask is geometry, not behavior — the model never "decides" to attend to itself first; there is nothing else there.
🔮 Predict Before You Compute
Three heads, each with its own random projection matrices. Will their attention matrices be identical?
Different numbers, and proudly meaningless ones. Each head multiplies by its own W_Q, W_K, W_V — so the nine matrices (3 layers × 3 heads) all differ. In a trained model you would read each head's pattern as a specialization (Module 04's hand-crafted heads showed the idealized versions). Here the differences are pure sampling noise: un-trained weights, un-trained differences. Knowing why they differ — and that "different" ≠ "meaningful" — is the whole section.

The MLP Grid — 64 Neurons, Firing Per Token

Attention decides what to look at; the MLP decides what to think about it. Each token's vector is projected to 64 neurons, gated by SiLU, and projected back — the widest, most parallel part of the engine. This lab shows the real activations of every neuron on every token, and animates a token through the grid.

The grid is position-wise: each token's row passes through the MLP alone — no mixing with neighbors. With un-trained weights the firing pattern is noise, but the shape of the computation is exactly what a trained model runs: 24 dims → 64 gated neurons → 24 dims, and only the 64→24 projection's output is added back to the stream.
$$\text{SwiGLU}(x) = \big(\text{silu}(x W_g) \odot x W_u\big) W_d, \qquad \text{silu}(z) = \frac{z}{1+e^{-z}}$$

Why a gate? The gate projection W_g decides which features the token wants right now; the up projection W_u supplies candidate values; the element-wise product keeps only the gated candidates; W_d folds the survivors back into 24 dims. A neuron whose gate is near 0 contributes nothing — it is off. That is the whole story of "which neurons fire on which tokens": the gate is the light switch.

🔬
The real-world version of this grid: in trained models, individual MLP neurons famously specialize — the "ancient Rome" neuron in GPT-2, the "chemical element" neuron in Llama. Our toy grid has no such structure (nothing trained it), which is why the honest readout says so. Module 12 will show you the real thing, and how researchers find those neurons with exactly this kind of grid.
🔁
Attention vs MLP, one sentence: attention is the only place tokens exchange information (rows of the score matrix); the MLP is the only place each token's vector is transformed alone (rows of the neuron grid). Everything else in the engine is plumbing between these two.

The break-it invitation

Type a long sentence, then sweep the layer pills: the same token produces a different grid at each layer, because its vector has been rewritten by attention first. Ask "what should happen?" — the honest answer is that with toy weights, nothing meaningful happens: the grids change, and the changes are noise. That predictability of what changes is the mechanism; the why requires training, which is Module 05's job.

🔮 Predict Before You Compute
The MLP processes each token's vector. Can information from token 3 reach token 7 through the MLP alone?
No. The MLP applies the same function to each token's row independently — no off-diagonal interaction exists. This is why the transformer alternates them: attention spreads information across tokens, the MLP computes on what arrived, attention spreads again. If the MLP could mix tokens, the causal mask would be pointless — and if it couldn't transform, the model would just be a retrieval system. The division of labor is load-bearing.

SECTION 7.6 ★

The Residual Stream — The Highway the Token Rides

Every layer adds to the token's vector instead of replacing it: x ← x + Attn(x) + MLP(x). The same 24-dim vector runs through all three layers, accumulating edits. This lab projects the token's real trajectory into 2D (PCA of the embedding table) and lets you watch the vector evolve, stage by stage.

Why add, not replace?

If layer ℓ replaced the vector, gradients would have to survive layer after layer of multiplication — vanishing or exploding (Module 05's nightmare). With addition, the derivative of the stream w.r.t. itself contains the identity: ∂xₗ/∂xₗ₋₁ = 1 + ∂F/∂xₗ₋₁. The "1" is a highway: the gradient can flow straight through any layer, even one whose own path is dead.

The honest picture: with un-trained weights the trajectory wanders — each add nudges the vector, and the nudges are random. In a trained model you would see structure: early layers write syntax, later layers write meaning, and the logit lens (7.7) reads the stream at every stop along the way. The projection is PCA of the real embedding table — the 2D positions are a true linear shadow of the 24-dim reality, not a cartoon.
📓 Instruction Manual · The Gradient Highway

Page 1 · The Identity Term

H1Write one residual block as xₗ = xₗ₋₁ + F(xₗ₋₁). Differentiate both sides:

$$\frac{\partial x_{\ell}}{\partial x_{\ell-1}} = I + \frac{\partial F}{\partial x_{\ell-1}}$$

The identity I means the gradient of the loss with respect to the stream at layer ℓ−1 gets the stream's gradient at layer ℓ added to it, untouched — through any number of layers. The chain rule never multiplies through a dead layer, because there is always the +1 lane. This is why transformers can train hundreds of layers deep while RNNs struggle past a dozen (Module 05 measured exactly this).

Page 2 · The Shared Workspace

The stream is not per-layer — it is one vector per token that every layer reads and writes. Researchers call it the residual stream: a shared workspace where attention deposits notes ("I read this context") and the MLP deposits edits ("here is the computation"). Because every layer writes into the same space, later layers see everything earlier layers wrote — nothing is overwritten, only appended.

This is why the logit lens (7.7) works at all: the stream at every depth is the same kind of object — a token's running summary — so the same unembedding can read it at any layer. The trajectory canvas above is literally the workspace, viewed from above.

Page 3 · Reading the Stream Is the Whole Field

Nearly every interpretability technique is a way of reading this stream: the logit lens decodes it (7.7), activation patching rewrites it and measures the consequences (Module 12), SAEs factor it into interpretable features (Module 12). The stream is the thing being interpreted; the layers are the machinery that edits it.

Anthropic's residual-stream work and the TransformerLens library both treat the stream as the canonical object of study. When you hear "where does the model store the subject?", the answer is always the same place: in the residual stream, at some layer, in some direction.

🔮 Predict Before You Compute
A layer's own computation path is broken (its gradient is zero). With a residual connection, can training still update the layers before it?
Yes — the highway bypass. ∂xₗ/∂xₗ₋₁ = I + ∂F/∂xₗ₋₁: even if ∂F = 0, the identity I still carries the gradient. This single "+1" is why residual networks (He et al., 2015) could train 152 layers when plain networks saturated at ~20, and why every transformer since 2017 ships with it. The canvas above shows the same geometry in the forward direction: each stage's arrow is F's contribution, and the stream itself — the highway — is the line between the dots.
SECTION 7.7 ★ FLAGSHIP SIGNATURE

The Logit Lens — Reading the Model's Mind at Every Layer

The residual stream at every depth is a token's running summary — so the same unembedding that produces the final logits can read any layer's stream and ask: "what would this layer alone predict?" That is the logit lens: a projection, not a magic window, and the most famous trick in transformer interpretability.

🎯 By the end of this section, you will be able to explain what the logit lens actually computes, what its honest limits are, and why "reading the model's mind" is a carefully qualified claim.

The honest reading: layer 0's column is essentially the embedding row speaking — near-uniform, because a raw embedding predicts nothing. Deeper columns reshuffle slightly as layers add their edits. In a trained model you would see the famous refinement: early layers confident in syntax, later layers converging on the true next token. Our toy shows the machinery without the training — the columns are computed live, and they are flat because the weights are honest placeholders.
$$\text{lens}_\ell = \text{softmax}\big(\text{RMSNorm}(x_\ell^{\text{stream}}) \cdot W_{te}^{\top}\big) \qquad \ell = 0, \ldots, L$$

Why does this work at all? Because the stream is one object: layer ℓ's vector is a genuine "prediction in progress" in the same space the unembedding reads. The lens simply asks the final readout head to evaluate an intermediate draft. The trick is a projection — it shows what the model's weights would say about that vector, not what the model is "thinking" (it isn't thinking; it's computing).

🔭
The research trail: the logit lens was popularized by "nostalgebraist" (2020, LessWrong) as a way to peek inside GPT-2; Neel Nanda's TransformerLens library made it a standard tool, and a whole literature of "tuned lenses" and "task-encoded vectors" grew from it. Every time you see a paper's "layer-by-layer accuracy" chart, you are looking at a logit lens at scale.
📓 Instruction Manual · The Lens, Its Proof, and Its Limits

Page 1 · The trick, in one line

L1Weight tying is the accidental enabler: because the unembedding is wteᵀ, the model already knows how to read vectors in embedding space. The lens just applies that reader at every depth instead of only at the end. In models without tying, the trick still works — the unembedding is still a fixed linear map trained to read stream-like vectors.

$$\text{logits} = \text{RMSNorm}(x) \cdot W_{te}^{\top} \quad \Rightarrow \quad \text{apply at any } x_\ell$$

Page 2 · What a "prediction" at layer ℓ means

Each column answers: "if the model stopped here and read the stream, what next character does the unembedding favor?" Early layers in trained models are confident in local syntax (the next character is likely a letter because we just saw one); the final layer is confident in the actual continuation. The shift between columns is the visible work of the layers: each layer moves the stream toward the answer.

The famous limitation: the lens is a projection into vocabulary space, and vocabulary space is not the model's whole mind. A model can know things that don't show up in next-token probabilities (see 7.9). Read the lens as a strobe light on one channel — not as a complete picture.

Page 3 · Honest limits of this module's lens

Our engine's lens readings are real computations — but the columns are flat, because the weights never learned to use the stream. Two consequences, both stated plainly: (1) this page shows the mechanics of the lens, which is the point; (2) the flatness is not a bug — it is the honest fingerprint of un-trained weights. When Module 12 points the same lens at a trained model, the columns will suddenly mean something — and you will know exactly why.

nostalgebraist (2020): "the logit lens is not a theory of how the model works — it is a way of looking." This page gives you the way of looking. The theory comes later.

You set temperature = 0. What happens to top-k — does it still matter?
No — top-k stops mattering. As T → 0, the ratio of any non-max logit to the max logit vanishes, so the distribution becomes the argmax with probability 1 — regardless of k. (Strictly, the sandbox floors T at 0.1, where the distribution is 99.9%+ on the argmax — the same greedy behavior, without dividing by zero.) This is the classic interplay question: two knobs, one greedy limit. Try it live and watch the top-5 bars collapse onto a single token.
SECTION 7.9

What the Telescope Can't See — The Honest Limits

Every instrument has a resolution limit. This telescope shows you every number in a working transformer — and that is exactly what it cannot show you: meaning. The features, circuits, and concepts a real model learns are not in the toy's 24 dimensions, and even a real model's activations only reveal meaning through careful analysis. Here is the honest inventory of what you have not seen.

🎯 By the end of this section, you will be able to state three things this module deliberately does not show — and where in the course each one gets built.

No Training, No Features

Every number on this page comes from un-trained weights. That means there are no features — no "letter detector" neurons, no "quote detector" circuits — because features are things gradient descent learns (Module 05). The telescope shows you the stage; the actors never arrived.

0training steps — the honest count for this engine

Superposition Is Invisible at This Resolution

Real models pack many features into each dimension — superposition (Anthropic's research program). With 24 dimensions and no training, there is nothing to disentangle; with 12,288 dimensions and heavy training, a single neuron holds dozens of overlapping concepts. Either way, raw activations are not a readable language. Sparse autoencoders (Module 12) are the microscope that makes them readable.

24dims — vs 4,096–12,288 in production models

The Logit Lens Is a Projection, Not a Mind

A model can "know" things that never surface in next-token probabilities — and a lens reading is a projection through one fixed map, not a transcript of thought. The lens shows what the weights would say about a vector; it does not show the vector's full role in the computation. Circuit analysis — tracing actual causal paths — is the tool for that, and it needs a trained model (Module 12).

1×projection — the lens reads vocab space, not "mind" space

The map of what comes next: Module 05 is where these weights would get trained (you already built the arena); Module 12 is where the real telescope lives — activation patching, SAEs, circuit extraction — pointed at genuinely trained models. This module is the bridge: you now know where every number lives, which is the prerequisite for asking what the numbers mean. You cannot interpret a machine you cannot open.
⚖️
The ethics of the lens, briefly: because the logit lens produces plausible-looking "predictions" at every layer, it is tempting to narrate them as thoughts — "the model is deciding…". Everything on this page is a computation, and every narrative reading of a computation is a metaphor. The rigorous habit — saying exactly what was computed, and never more — is the habit this whole course is training.
